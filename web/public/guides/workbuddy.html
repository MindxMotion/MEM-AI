把模型接入 WorkBuddy

一个 API 地址，一枚专用令牌。使用 OpenAI 兼容的 Chat Completions 接口。

准备令牌客户端配置独立验证排查问题

01 · 准备一枚专用令牌

  1. 打开网站并登录。首次使用请按站点提供的统一身份入口操作；普通自助注册可能未开放。
  2. 进入控制台的「令牌」页面，创建名为 WorkBuddy 的专用令牌，设置适当的额度与有效期。
  3. 复制 API Key，在客户端填写。不要把登录密码或管理员的个人访问令牌当作模型 API Key。
  4. 在「模型广场」核对可用模型和当前价格；最终可访问范围以此令牌的 GET /v1/models 结果为准。

API Key 是可消费额度的凭据，不要发到群聊、截图、工单或公开仓库。泄露后立即撤销并重新创建。

打开「设置 → 模型 / 自定义模型」，选择自定义 OpenAI 兼容供应商。不同版本的菜单名称可能不同。

  1. 先使用默认参数测试一轮纯文本对话，确认连接与基本响应。
  2. 需要流式输出时再开启流式；需要工具调用、图片输入或推理选项时，逐项启用并验证实际模型支持。不能假定同系列所有模型都支持全部能力。
  3. 保存并重新打开对话；客户端仍使用旧配置时，完全退出并重启后再试。

模型目录会随渠道状态变化。本文不固定模型总数、价格、上下文长度，也不把一次测试成功当作长期稳定性保证。

03 · 用独立请求区分配置与上游问题

下面是 macOS / Linux / Git Bash 的示例。先在本机设置 GATEWAY_API_KEY 与 GATEWAY_MODEL 环境变量，不要提交真实密钥到脚本仓库。

查询此令牌可用模型（不生成内容）

curl -sS -D - "$GATEWAY_BASE/models" \
  -H "Authorization: Bearer $GATEWAY_API_KEY"

一次最小对话（会产生实际调用费用）

curl -sS -D - "$GATEWAY_BASE/chat/completions" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d "{\"model\":\"$GATEWAY_MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"回复 OK\"}],\"stream\":false}"

需要检查流式时，将 stream 改为 true 并使用 curl -N。保留 HTTP 状态、响应中的请求 ID，以及流是否完整结束；不要分享 Authorization 请求头。

Python / OpenAI SDK

import os
from openai import OpenAI

client = OpenAI(
    base_url=os.environ["GATEWAY_BASE"],
    api_key=os.environ["GATEWAY_API_KEY"],
    max_retries=0,  # 诊断时先关闭客户端自动重试，避免误判
)
response = client.chat.completions.create(
    model=os.environ["GATEWAY_MODEL"],
    messages=[{"role": "user", "content": "回复 OK"}],
)
print(response.choices[0].message.content)

诊断时先关闭客户端自动重试，避免「客户端重发 × 网关重试」放大调用。已经收到部分输出或工具调用后，不要自动重放整次请求；超时也不一定表示上游没有执行。

04 · 遇到不稳定，保留这些信息

发生时间（含时区）、模型 ID、接口路径、是否流式、客户端版本、HTTP / 流内错误码、请求 ID。若有客户端重试，提供每次请求 ID 与次数；无需提供提示词、对话正文或密钥。

现象优先检查
401 / 403令牌是否正确、有效，分组和模型权限是否允许；额度不足的具体响应以返回错误为准。
404 / 无可用渠道Base URL 拼接、模型拼写、令牌模型列表和当前启用渠道。前台有资料不代表一定可路由。
400 / 不支持参数先移除非必需的采样、推理与工具选项，使用最小文本请求复现；不要持续重试同一无效参数。
429 / 502 / 503可能是限流、容量或上游故障；保留请求 ID，交由管理员对齐渠道与尝试记录。不要高频连续重发。
504 / 524 / 长时间等待检查客户端、入口代理与上游超时；未知执行结果不宜盲目重放。
HTTP 200，但输出中断检查 SSE 错误事件、完整结束事件、客户端取消和连接断开。HTTP 200 不代表生成完整成功。
网关会自动换渠道或模型吗？

只在配置的重试预算和规则允许时，网关才会对同一模型再次选路。严格会话绑定、固定渠道或已开始输出会限制安全重试。不会为掩盖故障而自动换成另一种模型；没有其它可用渠道时应返回明确错误。

什么可以证明接入稳定？

「测试连接」只证明某次调用。稳定性需结合一段时间内同模型、同接口的成功率、耗时、错误类别和流结束状态分析。客户端自己的重试需要与网关尝试分别统计。

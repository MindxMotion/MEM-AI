Ephemeral-cache lifecycle

No PVC, RDB or AOF. Restart discards cached users/tokens/sessions, auth fences/tombstones, subscription/affinity caches, rate counters and active Redis metrics. MySQL remains authoritative. user_cache.go and user_session.go hydrate cache misses from SQL and check current auth/session state; token_cache.go guards cold fills with fences. No data restore or credential rotation is part of a Redis restart.

Do not assume cache loss preserves every transient security barrier. For planned Redis replacement, parent must quiesce New API and drain its in-flight/auth mutations before Redis replacement, then cold-start New API against the same database. This prevents pre-restart snapshots from repopulating lost fences. Unexpected simultaneous Redis loss and in-flight auth mutation remains an application-level race to verify, not a claimed guarantee. This operation never stops/restarts MindMotion. Rate windows and affinity choices reset; lost transient metrics and Pub/Sub events are not replayed.

128Mi/noeviction is a bounded starting configuration, not a full-load claim. 192Mi includes the process, client overhead and tmpfs; OOM or maxmemory rejection remains possible under load. Parent must verify database-authoritative authentication/revocation after cold restart and source behavior on cache errors.

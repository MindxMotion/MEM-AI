2. Decisions and smallest slice

DEC-001 — Extend existing ownership, not a supplier adapter or plugin framework.
Use channel-billing.go for profile selection and normalization, existing service transport for network safety, and the channels feature for presentation. Add typed opt-in upstream_balance under ChannelOtherSettings. It works for single-key OpenAI and Anthropic inference channels without changing their types. Reject a provider-name switch, copied external application store, scripts and new balance microservice.
DEC-002 — Legacy subscription/usage first; relative endpoint overrides included.
The selected profile reads hard_limit_usd and total_usage, with usage scale 0.01. Defaults are /v1/dashboard/billing/subscription and /v1/dashboard/billing/usage. Administrators may configure alternative root-relative paths, currency/unit and declared account/key scope. The first slice uses cumulative usage without date query parameters and requires a matching cumulative total; monthly/rolling budget semantics are unsupported rather than mixed. All amounts in a pair must describe the same scope, period and unit.
DEC-003 — No speculative arbitrary JSON mapper.
Existing advanced-custom route configuration covers endpoint routing, but its converter/raw-response behavior does not establish a normalized quota contract. Leave that legacy feature intact. If a redacted response proves a different numeric shape is required, reopen this design for one GET response with bounded object-key/index paths, fixed decimal scales and explicit unit/scope; no JSONPath evaluation, expressions, scripts, request bodies or custom secret headers. Endpoint overrides already satisfy nonstandard paths with the supported response shape; different shapes fail explicitly.
DEC-004 — Informational account snapshot, not gateway accounting.
Cache normalized snapshots in bounded process memory, not channel.settings or a new table. Do not write Channel.Balance, local UsedQuota, user credits, pricing, token quota or channel status. Do not feed this path into the legacy bulk auto-disable loop. Configured rows show the new upstream snapshot separately from labeled local consumption; unconfigured rows retain legacy balance behavior. Reject a chart built from local usage plus upstream remaining and reject persistent history in this slice.
DEC-005 — Display each shared account once when summarized.
For identical origin, credential and effective profile configuration, deduplicate fetches and snapshot identity server-side. Two model/protocol channels can show the same account snapshot with a “shared account” label. Do not sum their totals. Do not treat channel tags, model names or matching origins alone as account identity. This slice has no cross-account grand total or history dashboard.

3. Caller-visible contracts and trust boundary

Configuration and authorization

UPSTREAM_BALANCE_ORIGINS is a server-only environment map from neutral aliases to exact HTTPS origins, for example {"primary":"https://example.com"}. Missing configuration disables the new outbound capability; malformed configured values fail startup. Origins have no path, userinfo, query or fragment. The channel form selects an alias and profile and sets optional endpoint paths plus unit/scope confirmation. Real targets stay in deployment configuration; never put them in defaults, public fixtures, docs or VITE variables.

The same saved channel key supplies server-side Bearer authentication, even for an Anthropic inference channel. No second key field, query authentication, credential interpolation or header override is allowed in this profile. Multi-key and task-plugin channels return unsupported. New settings preserve omitted/unknown unrelated JSON fields; masked or empty key form values must not replace the saved key. Changing billing destination, paths, profile, unit or scope requires channel.sensitive_write; ordinary unchanged settings resubmission must remain available to channel.write administrators.

Proposed GET /api/channel/:id/upstream_balance reads a cached normalized snapshot only, under AdminAuth + channel.read. Proposed POST /api/channel/:id/upstream_balance/refresh performs a bounded query under AdminAuth + channel.operate, existing critical rate limiting and trusted-origin/session protections. Declare personal-access-token permission scopes through the existing permission-route helper. No ordinary-user, public status, wallet or model-list endpoint includes these amounts or metadata. Browser requests use the shared Axios client so the existing /new-api/ mount is applied exactly once.

Outbound transport and response normalization

Resolve aliases on the server; accept only root-relative, non-network-path endpoint paths with no query, fragment, backslash, percent-encoded traversal or dot segments. Combine them with the selected exact origin; never with browser input or an inference URL suffix. Reject redirects rather than forward authorization. Use certificate verification and direct protected dialing, with private/reserved IPv4/IPv6 rejected for every resolved address and the validated address pinned at connection time. Do not inherit channel/global proxies, TLS-insecure flags, arbitrary Host/header overrides or globally disabled SSRF protection. Reuse service protected-fetch mechanics with policy injection; do not retrofit all inference clients.

A single cancellation/deadline covers both GET requests, DNS, headers and body reads. Cap each decoded body at the existing advanced-balance 256 KiB ceiling, including compressed responses; bound JSON depth, and close bodies on success/failure. HTTP failure, error objects, missing fields, wrong numeric types, non-finite/unrepresentable values or mismatched semantics are failures, never zero. Accept finite nonnegative total and used; derive remaining = total − used, including a negative overdrawn value. Use existing decimal arithmetic for normalization; expose finite bounded numbers with explicit unit precision. The profile never guesses unlimited from a large sentinel amount.

The API keeps the usual success/message envelope and returns a whitelisted snapshot: nullable total, used and remaining; currency or quota unit; display precision; account/key scope; declared usage period; server checkedAt; freshness/status; and an opaque shared-account reference. Only supported, known quantities are populated. It returns no key, target origin, response body, headers, upstream account identifier, traceback or supplier identity. Stable safe error categories distinguish unsupported, configuration, authorization, timeout, unavailable and invalid response; logs contain only channel ID, category and duration, not remote errors or amounts.

Cache and race behavior

Use a process-private keyed credential fingerprint plus normalized origin and effective profile configuration for cache identity; never expose or log the fingerprint. Authorize each requesting channel before any cache lookup. Bound entry count and outbound concurrency, coalesce concurrent refreshes and enforce a server cooldown. Repeated clicks inside the freshness interval return the existing snapshot; no force-refresh bypass, background polling, inference test or paid model call is needed. Client refresh disables duplicate actions.

A failed refresh retains the last successful snapshot and its checkedAt with an error/stale state; an unqueried/restarted cache reports unknown, not the old float default zero. Freshness and expiry intervals must be fixed and documented in the test contract before implementation. Config/key edits change cache identity; recheck configuration before publishing an in-flight result. Invalidate affected frontend queries on save/logout. Closing or switching a dialog prevents a late result from updating another channel. Cached amounts do not persist across logout in browser storage. Multiple backend replicas may each query once; no Redis/distributed-lock infrastructure is justified for this slice.
